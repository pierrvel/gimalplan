# 오늘 화면 + AI 배치 전용화 설계

날짜: 2026-11-16
상태: 검토 반영본 (사용자 승인 대기)

## 의도와 이유

사용자는 고등학생이고, 기말고사 플래너를 **주로 폰과 패드에서** 씁니다. 열었을 때 바로 알고 싶은 것은 두 가지입니다.

1. **오늘 해야 할 일**
2. **이 계획이 끝나려면 앞으로 얼마나 더 해야 하는지.** 과목에 따라 세 가지 방식으로 생각합니다.
   - "몇 시간 남았다"
   - "몇 개 남았다"
   - "하루에 이만큼씩 하면 된다"

직접 계획을 짜면 특정 과목만 파게 돼서, 시험 일정에 맞춰 과목을 고르게 배분하려고 AI를 도입했습니다. 그런데 실제로 써 보니 두 가지 문제가 있었습니다.

- **AI가 처음 넣은 계획보다 훨씬 많은 계획을 만든다.**
- **무엇이 바뀌고, 지워지고, 생겼는지 전혀 알 수 없다.**

무엇을 공부할지는 사용자가 정합니다. 학원 숙제 같은 변수도 생기기 때문입니다. AI는 **사용자가 정한 체크리스트를 시간표에 고르게 배치하는 역할만** 맡습니다.

## 목표

- G1. 폰과 패드 폭에서 앱을 열면 "오늘" 화면이 기본으로 보인다. 오늘 할 일 목록이 맨 위에 있고, 그 아래에 과목별 남은 양이 나온다.
- G2. 과목별 남은 양을 **남은 개수 · 남은 시간 · 하루 필요량** 세 가지로 함께 보여준다.
- G3. AI는 기존 체크리스트 항목을 배치하기만 한다. 항목 추가, 삭제, 이름이나 예상 시간 변경을 하지 않는다. 항목마다 배치되는 시간의 합은 그 항목의 예상 시간을 넘지 않는다.
- G4. AI 결과를 적용하기 전에 무엇이 추가되고, 이동하고, 빠지는지를 항목 단위로 보여준다. 다 배치하지 못한 시간도 보여준다.
- G5. 눈에 띄는 가독성 문제를 고친다.
  - 시간표의 시각 라벨에 오전·오후 구분이 없는 문제
  - 데스크톱 툴바의 버튼 글자가 줄바꿈되는 문제

## 하지 않는 것 (Non-goals)

- 데스크톱(가로 960px 이상)의 2열 레이아웃 전면 개편
- AI 없이 앱이 직접 배치하는 알고리즘 (나중에 고려할 수 있음)
- AI가 체크리스트 항목을 제안하는 기능 (이번에는 명시적으로 제외)
- 동기화(Firestore) 구조 변경, 데이터 스키마 변경
- 예전 AI 실행으로 부풀어진 기존 체크리스트 데이터의 자동 정리나 검토 화면. 사용자가 체크리스트에서 직접 고칩니다(사용자 결정).

## 실패로 간주하는 것 (Anti-goals)

- 적용 후 체크리스트 항목의 개수나 예상 시간이 사용자 모르게 바뀌는 것
- AI 적용 후 "남은 양" 숫자가 부풀어 보이는 것
- 첫 화면에서 오늘 할 일을 보려고 스크롤하거나 탭을 이동해야 하는 것

## 제약

- 기존 스택을 유지합니다: React 19, Vite, Tailwind 4, lucide-react, Firebase, Gemini(`@google/genai`), Vercel 서버리스(`api/schedule.js`).
- 데이터 타입(`src/types/planner.ts`)은 바꾸지 않습니다. 동기화된 기존 사용자 데이터가 그대로 동작해야 합니다.
- 기존 vitest 테스트(`aiScheduler.test.ts`, `sync.test.ts`, `availability.test.ts`, `App.test.tsx`)는 새 동작에 맞게 갱신하고 모두 통과해야 합니다.
- UI 문구는 한국어입니다.

## 검토한 방식과 선택

배치를 누가 하느냐에 대해 세 가지 방식을 비교했습니다.

| 방식 | 내용 | 트레이드오프 |
|---|---|---|
| **① Gemini 유지 + 앱이 엄격히 거르기 (선택)** | 프롬프트를 "배치만"으로 바꾸고, 앱이 결과를 거름(항목별 시간 상한, 없는 항목 연결 금지, 체크리스트 불변) | 대화형 수정과 고정 규칙을 그대로 쓸 수 있음. 대신 네트워크와 API 키가 필요하고, 느리고, 결과가 매번 조금씩 다름 |
| ② 앱이 직접 계산해서 배치 | 시험이 가까운 과목, 남은 양이 많은 과목 순으로 빈 시간을 돌아가며 채움 | 즉시 결과, 무료, 결과 고정. 자연어 수정과 규칙은 쓸 수 없음 |
| ③ 섞기 | 초안은 ②로, 말로 하는 수정은 ①로 | 양쪽 장점이 있지만 구현량이 가장 많음 |

**①을 고른 이유:** 겪은 문제의 원인은 AI를 쓴 것 자체가 아니라, 결과를 거르지 않은 데 있습니다. 거르는 장치만 넣으면 문제가 사라지고, 이미 만들어 둔 대화형 수정도 살릴 수 있습니다.

첫 화면은 시안 세 가지(A: 오늘 목록 먼저 / B: 과목 카드 / C: 요약 먼저) 중 사용자가 **A**를 골랐습니다.

## 설계

### 1. "오늘" 화면 (가로 960px 미만)

현재 상단 탭은 `타임라인 | 체크리스트` 두 개입니다. 이를 **`오늘 | 시간표 | 체크리스트`** 세 개로 바꾸고, 기본 탭을 `오늘`로 합니다. 탭바는 엄지가 닿기 쉬운 화면 하단에 둡니다(*제 결정*). 시간표와 체크리스트 화면은 지금과 같은 내용입니다.

```
오늘 · 11.16 (월)                 D-17
공부 가능 18:00–24:00 · 계획 4시간 30분

오늘 할 일
☐ 수특 프린트 9회   18:00–19:00  [영어Ⅱ]
☐ 정적분 정의 복습  19:10–20:40  [미적분Ⅰ]
☐ PPT 정리본 보기   21:00–22:30  [인문윤리]

과목별 남은 양
영어Ⅱ        ▓░░░░  5개 · 4.5h · 하루 16분
인문학과윤리  ░░░░░  4개 · 4h  · 하루 14분  ⚠ 밀림 1h
미적분Ⅰ      ▓▓░░░  3개 · 3.5h · 하루 12분
…
─────────────────────────────────
 [오늘]   시간표   체크리스트
```

**오늘 할 일**
- 오늘 날짜의 공부 블록(`study`, `final_prep`)을 시간순으로 나열합니다. 시험 블록(`exam`)과 고정 일정(학교, 식사)은 넣지 않습니다(*제 결정*).
- 체크박스는 블록 완료를 토글합니다. 체크리스트 항목의 완료 규칙은 아래 "완료 규칙"을 따릅니다.
- 항목을 탭하면 기존 블록 편집 모달(`StudyBlockModal`)이 열립니다.
- 오늘 할 일이 없으면 빈 상태 문구와 함께 "시간표에서 추가" 및 "AI로 배치" 버튼을 보여줍니다.

**완료 규칙 (사용자 결정: 모든 블록을 체크해야 완료).** 기존 `toggleStudyBlock`을 바꿉니다.
- 항목에 연결된 블록이 여러 개면, **모든 블록이 완료됐을 때만** 항목이 완료됩니다. 하나라도 체크를 풀면 항목도 미완료로 돌아갑니다.
- 연결된 블록이 없는 항목은 지금처럼 체크리스트 체크박스로 직접 완료합니다.
- 체크리스트에서 항목을 직접 체크하는 기존 동작은 유지합니다.
- **항목의 남은 시간**은 다음과 같습니다. 완료된 항목은 0입니다. 미완료 항목은 max(0, `estimatedMinutes` − 완료된 연결 블록 시간의 합)입니다. 이 정의를 "오늘" 화면과 AI 배치(`remainingMinutes`)에서 똑같이 씁니다.

**과목별 남은 양.** 시험이 끝나지 않은 과목만 시험일 순으로 보여줍니다.
- **남은 개수**: 완료되지 않은 체크리스트 항목의 수
- **남은 시간**: 그 과목 항목들의 남은 시간 합계 (위의 완료 규칙 참고)
- **하루 필요량**: 남은 시간 ÷ 오늘부터 시험 전날까지의 날수(최소 1). 시험 전날까지 끝내는 것을 기준으로 합니다(*제 결정*).
- **진행 막대**: (전체 예상 시간 − 남은 시간) ÷ 전체 예상 시간
- **⚠ 밀림 표시**: 오늘 이전 날짜에 배치됐는데 완료되지 않은 그 과목 블록의 시간 합계가 있으면, "밀림 Nh"로 보여줍니다(*제 결정*). "다른 과목보다 적다" 같은 상대 비교는 기준이 모호해서 쓰지 않습니다.
- 과목 줄을 탭하면 체크리스트 탭으로 이동하고, 해당 과목 필터가 선택됩니다.

**가로 960px 이상 (가로로 든 패드, 데스크톱).** 사용자는 패드를 가로로 쓰는 경우가 많습니다.
- 2열 레이아웃은 유지하되, **왼쪽 칸 상단에 `오늘 | 시간표` 전환**을 두고 기본값을 `오늘`로 합니다(*제 결정*).
- 오른쪽 칸은 지금처럼 체크리스트입니다.
- 왼쪽 칸의 "오늘" 화면은 위의 오늘 할 일과 과목별 남은 양을 그대로 씁니다. 같은 컴포넌트를 재사용합니다.

### 2. AI 배치 전용화

**프롬프트 (`buildAiSchedulePrompt`)**
- 체크리스트를 바꾸라는 규칙(현재 규칙 5의 일부와 규칙 6)을 지웁니다.
- 다음 규칙으로 대체합니다.
  - 모든 블록은 `pendingChecklistItems`의 `id` 중 하나를 `checklistItemId`로 가져야 한다.
  - 항목마다 배치 시간의 합은 `remainingMinutes`를 넘지 말아야 한다.
  - 모든 빈 시간을 채울 필요는 없다.
- 각 항목의 `remainingMinutes`는 "완료 규칙"의 남은 시간에서, 시작일 이후에 보존되는 미완료 블록(직접 만든 블록) 중 그 항목에 연결된 블록의 시간 합을 뺀 값입니다. 0 이하인 항목은 목록에서 뺍니다. 완료 여부는 항목의 `completed`가 아니라 이 값으로 판단합니다.
- 고르게 배분하라는 지시를 명시합니다. "각 과목의 남은 시간을 그 과목 시험일까지 날짜에 고르게 나누고, 하루에 한 과목만 몰지 말 것."
- 사용자의 자연어 지시는 배치 조정용입니다. 항목 추가나 삭제를 요청받으면 수행하지 않고, rationale에 "체크리스트 수정은 직접 해 주세요"라고 안내합니다.

**응답 스키마.** `api/schedule.js`와 `aiScheduler.ts` 양쪽에서 `checklistUpdates`를 제거합니다. `checklistItemId`는 필수로 바꿉니다.

**검증 (`validateAndSanitizeAiBlocks`).** 기존 검사(기간, 시험일, 가용 시간대, 15분 최소, 직전보강 상한, 겹침)는 유지하고 다음을 더합니다.
- `checklistItemId`가 미완료 항목이 아니면 그 블록은 버립니다(`skippedInvalid`로 집계).
- 블록의 `subjectId`와 `title`은 연결된 항목의 값으로 덮어씁니다. 같은 항목이 여러 블록으로 나뉘면 기존 방식대로 " (1/2)" 같은 접미사를 붙입니다.
- 항목별 남은 시간을 날짜순으로 차감합니다. 남은 시간보다 긴 블록은 끝 시각을 잘라내고, 남은 시간이 15분 미만이면 블록을 버립니다(`trimmedForBudget`로 집계).
- **체크리스트는 손대지 않습니다.** `synchronizeChecklistWithAiBlocks`의 항목 생성·수정·예상 시간 재계산 로직을 제거합니다.
- 결과의 `checklistItems`는 입력과 같은 배열입니다. 적용할 때도 블록만 교체합니다.

**지난 블록 처리 (*제 결정*).**
- 다시 생성할 때 교체하는 대상은 **시작일 이후**의 미완료 AI 블록뿐입니다. 시작일 이전의 미완료 블록(AI든 직접 만든 것이든)은 그대로 남겨, "⚠ 밀림" 표시의 근거로 씁니다. 이 블록들은 미리보기의 "빠짐"에도 나오지 않습니다.
- 지난 미완료 블록은 공부하지 않은 시간이므로 남은 시간에서 빼지 않습니다. 그래서 그 시간은 앞으로의 날짜에 다시 배치될 수 있습니다.
- 남은 시간에서 빼는 것은 다음 둘입니다. 완료된 블록의 시간, 그리고 시작일 이후에 보존되는 미완료 블록(직접 만든 블록)의 시간입니다.

**체크리스트와 연결되지 않은 블록 (*제 결정*).** 예전 AI 블록과 일부 직접 만든 블록에는 `checklistItemId`가 없습니다. 이런 블록이 교체 대상이면 미리보기의 "빠짐"에 "항목 없는 블록" 묶음으로 따로 보여줍니다. 보존 옵션을 껐을 때 이 블록이 지워지는 건 지금과 같은 동작이지만, 이제는 미리보기에서 보입니다.

**미배치 계산.** 항목별 남은 시간에서 실제 배치된 시간을 뺀 값을 결과에 담습니다(`unplacedByItem`).

### 3. 적용 전 변경 내역 (AiPlanModal 미리보기)

비교 기준은 다음 둘입니다.
- **이전**: 이번 생성으로 교체될 기존 AI 블록. `preserveCompletedAndManual`이 켜져 있으면 완료되지 않은 AI 블록, 꺼져 있으면 보존되지 않는 블록 전부입니다.
- **이후**: 새로 생성된 AI 블록

이 둘을 **체크리스트 항목 단위로 묶어** 비교합니다.

```
요약: 배치 12시간 / 남은 계획 15시간 · 미배치 3시간

+ 추가 (4)   수특 프린트 10회      11.17 18:00–19:00
↔ 이동 (3)   정적분 정의 복습      11.18 19:00 → 11.17 21:00
− 빠짐 (1)   교과서 문풀           11.19 18:00–19:30
· 그대로 (6) (접힘)

미배치: 인문학과윤리 · 수특 신행 90분, …
```

- **추가**: 이전에는 블록이 없었고 이후에 생긴 항목
- **이동**: 양쪽에 다 있지만 날짜나 시간이 달라진 항목. 이전과 이후의 시간 목록을 함께 표시합니다.
- **빠짐**: 이전에는 있었지만 이후에 블록이 없는 항목
- **그대로**: 날짜와 시간이 모두 같은 항목. 기본으로 접어 둡니다.
- 맨 위 요약에 "배치 / 남은 계획 / 미배치"를 보여줍니다. 미배치가 있으면 항목별 목록도 보여줍니다.
- 기존의 rationale 문단은 요약 아래에 작게 남깁니다.
- 대화형 수정을 이어서 할 때는 직전 미리보기를 "이전"으로 삼아 변화를 보여줍니다. 그래서 각 수정이 무엇을 바꿨는지 알 수 있습니다.

### 4. 가독성 수정

- 시간표의 시각 라벨을 24시간제(`06`, `07` … `13`, `14` … `23`)로 바꿉니다.
- 데스크톱 툴바의 버튼(`오늘`, `시험 시작일`, `고정일정 숨김`)에 줄바꿈 금지를 적용합니다. 공간이 부족하면 가로 스크롤 대신 아이콘만 남기는 식으로 축약합니다(*제 결정*).
- 체크리스트 과목 필터 탭의 가로 스크롤바를 숨깁니다. 스크롤 동작은 유지합니다.

## 만드는 사람에게 맡기는 것

- "오늘" 화면 컴포넌트의 파일 구성과 이름(예: `TodayPane.tsx`), 그리고 남은 양 계산 함수를 어디에 둘지(예: `src/utils/progress.ts`)
- 미리보기 비교 로직을 순수 함수로 분리하고 테스트를 추가하는 방식
- 세부 스타일(간격, 색)은 기존 Tailwind 톤과 `.agent/skills/clean-ui/SKILL.md`를 따릅니다.
